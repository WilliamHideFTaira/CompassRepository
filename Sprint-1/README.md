### Sprint 1: Git e Github

#### Git

Git é a ferramenta de controle de versão mais usada no mundo atualmente. Baseia-se em repositórios, contendo branches, todas as versões do código e cópias de cada desenvolvedor, é otimizado para alto desempenho e protegido com criptografia. 

A operação no Git é por meio de um terminal, com comandos que podem ser agrupados por função:

* [Comandos Fundamentais](./Comandos-fundamentais) (comandos rotineiros de clonagem de repositório, envio de alterações e outros);
* [Comandos de Branches](./Comandos-branches) (comandos que gerenciam versões diferentes do projeto);
* [Comandos de atualização e compartilhamento de repositórios](./Comandos-att-comp) (comandos que auxiliam no compartilhamento do repositório com outros desenvolvedores);
* [Comandos de análise e inspeção de repositórios](./Comandos-analise-insp) (comandos para verificar andamento do projeto, com informações sobre commits, tags e outros);
* [Comandos de administração de repositórios](./Comandos-administracao) (comandos de gerência para otimização do repositório);

O GitHub é um dos serviços de gerenciamento de repositórios, gratuito e é onde ficam armazenados os projetos, podendo serem disponibilizados para todos ou mantê-los privados.

Ao entrar na página de um repositório, nota-se várias abas: 
* **Code** - é onde fica informações importantes, como o código fonte, o README.md (documentação do projeto), detalhes da licença (política que desenvolvedores usam para determinar como outros usuários podem utilizar, modificar e redistribuir seus projetos);
* **Issues** - aba para criar tarefas para melhorias ou correção de bugs do projeto (é necessária uma _label_ e um _responsável_);
* **Pull Requests** - área onde os _colaboradores_ (desenvolvedores autorizados) enviam código para ser analizado;
* **Actions** - é onde se cria automatizações de deploy com integração em outros serviços;
* **Projects** - aba onde é possível criar um projeto e utilizar um quadro de tarefas, auxiliando na organização do seu time;
* **Wiki** - documentação extensa do projeto. Anotações como funcionalidades, bugs conhecidos e não solucionados ficam nessa aba;
* **Insights** - informações detalhadas do projeto, como: contribuidores, commits, forks. Ajudam na visualização da evolução do projeto;
* **Settings** - onde ficam as configurações do projeto, onde adiciona colaboradores, altera informações do repositório, entre outras funções.
